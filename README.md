# RiskLens

Текущая версия: **0.5.0**. [Batch, контракты и lifecycle 0.5.0](docs/CHANGES-0.5.0.md). [Исправления API и диагностика 0.4.0](docs/CHANGES-0.4.0.md). [Новые возможности и проверки 0.3.0](docs/CHANGES-0.3.0.md). [Исправления навигации, расхода памяти и контекста](docs/FIXES-0.2.0.md). Отчёт `docs/REPORT.md` и исходный `benchmark.json` относятся к 0.1.0; новые измерения хранятся отдельно.

Локальный инструмент анализа Go-кода для GigaCode: типизированная навигация, связи вызовов и обращений к полям, текстовый и векторный поиск, сборка контекста. MCP `stdio` — интерфейс доступа к анализатору. Сервер не содержит LLM-агента, не генерирует аннотации и не редактирует исследуемый код.

## Быстрый старт

Нужны Go **1.26+** в `PATH` и Python **3.10–3.12** с подходящими CPU wheels. Фактически проверены Go 1.26.6, Python 3.11.2, macOS 14.1.1 arm64. Сборки Linux amd64 и Windows amd64 проверяются отдельно; запуск на них не заявляется проверенным. Подробности — [отчёт](docs/REPORT.md).

Из корня `risklens` выполните установочный шаг с интернетом:

```sh
go mod download
python3.11 -m venv .venv
.venv/bin/python -m pip install -r runtime/requirements-lock.txt
.venv/bin/python runtime/setup_model.py --output models/e5-small
.venv/bin/python scripts/configure.py \
  --root examples/strategy \
  --python .venv/bin/python \
  --model-dir models/e5-small \
  --output config.local.json
```

`configure.py` сохраняет абсолютные пути. Для своего репозитория замените `--root`. Корень должен содержать единственный анализируемый `go.mod`; вложенные модули пропускаются. Используйте отдельный cache для каждого проекта/процесса.

Windows PowerShell:

```powershell
go mod download
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r runtime/requirements-lock.txt
.venv\Scripts\python.exe runtime/setup_model.py --output models/e5-small
.venv\Scripts\python.exe scripts/configure.py --root examples/strategy --python .venv/Scripts/python.exe --model-dir models/e5-small --output config.local.json
```

Подготовьте зависимости **исследуемого** проекта отдельным установочным шагом `go mod download` в нём. Анализатор не загружает зависимости и toolchain из интернета. Он использует `GOPROXY=off`, `GONOPROXY=none`, `GOSUMDB=off`, `GOVCS=*:off`, `GOTOOLCHAIN=local`, `GOWORK=off` и `-mod=readonly`; `go.mod`/`go.sum` не меняет. Локальные `replace` должны быть доступны на диске; их исходники не индексируются, если находятся за пределами выбранного модуля.

**Предпочтительный способ запуска — `go run` через stdio под управлением GigaCode.** После подготовки окружения запуск из корня RiskLens работает офлайн:

```sh
go run ./cmd/risklens-mcp --config config.local.json
```

Это MCP-сервер, ожидающий JSON-RPC на stdin. Отсутствие обычного текста в терминале нормально. Протокольный stdout отделён от диагностического stderr. Для проверки без MCP-клиента:

```sh
go run ./cmd/risklens-mcp --config config.local.json --wait-vectors --tool index_status
go run ./cmd/risklens-mcp --config config.local.json --tool search_symbols --args '{"query":"Calculate","limit":10}'
go run ./cmd/risklens-mcp --config config.local.json --wait-vectors --tool search_code --args '{"query":"льготный период обучения","limit":5}'
```

Перед одноразовой проверкой остановите постоянный сервер либо укажите отдельный `--cache`. Одноразовый запуск заново загружает Go-модуль. Для постоянной работы используйте один MCP-процесс. `--wait-vectors` обязателен в одноразовом запуске, если нужны готовые векторы. Без настройки embeddings можно использовать `--root /path/to/module`: точная навигация и текстовый поиск работают, статус сообщает `vectors=degraded`.

## Подключение GigaCode

Зарегистрируйте сервер с именем `risklens-mcp` и транспортом `stdio`.

### Предпочтительный способ: go run

Рекомендуется поручить GigaCode запуск MCP через `go run`: отдельная служба и предварительная сборка бинарника не требуются. Укажите transport `stdio`, command — абсолютный путь к Go 1.26+, args — отдельные элементы массива:

```json
{
  "command": "/absolute/path/to/go",
  "args": [
    "-C", "/absolute/path/to/risklens",
    "run", "./cmd/risklens-mcp",
    "--config", "/absolute/path/to/risklens/config.local.json"
  ]
}
```

Это поля запуска процесса, не проверенная полная схема GigaCode. [Шаблон go run](docs/gigacode-go-run.template.json) переносится в формат вашей версии клиента. `-C` выбирает каталог исходников RiskLens независимо от открытого в IDE проекта; исследуемый проект задаётся `root` в config. Все пути замените на свои. Каталог выбранного Go также должен быть в PATH клиента для загрузки исследуемого модуля.

Для проверки в терминале:

```sh
go -C /absolute/path/to/risklens run ./cmd/risklens-mcp --config /absolute/path/to/risklens/config.local.json
```

Процесс ждёт MCP-сообщений на stdin; его запускает клиент при подключении, закрытие stdin завершает сервер и workers. Не добавляйте `&`, `nohup` или `--tool`. `go run` компилирует исходники при запуске и использует Go build cache, поэтому первый старт медленнее готового бинарника. Один MCP-процесс обслуживает последующие вызовы инструментов. После изменения исходников перезапустите подключение. Зависимости RiskLens и модели установите заранее по инструкции выше; офлайн-запуск требует заполненного Go module cache.

Проверка этого способа запуска официальным SDK:

```sh
.venv/bin/python scripts/sdk_smoke.py --go-run --config /absolute/path/to/risklens/config.local.json
```

### Альтернатива: готовый бинарник

Если нужен запуск заранее собранной версии, выполните `go build -trimpath -o bin/risklens-mcp ./cmd/risklens-mcp` и укажите command `/absolute/path/to/risklens/bin/risklens-mcp`, args `["--config", "/absolute/path/to/risklens/config.local.json"]`. Для предпочтительного запуска через `go run` этот шаг не требуется.

На Windows имя файла — `risklens-mcp.exe`. У клиентского процесса должны быть Go 1.26+ в PATH и доступ к подготовленному модульному кэшу. Активную версию внешней команды Go показывает `environment.GOVERSION`; `environment.toolchain` — версия сборки самого сервера.

[Шаблон подключения](docs/gigacode-connection.template.json) **концептуальный, его ключи не являются проверенной схемой конфигурации GigaCode**. Версия GigaCode в окружении разработки отсутствовала. Перенесите command/args в документированный вашей версией формат. Интероперабельность `stdio` проверена официальным Python SDK `mcp==1.26.0`, но это не проверка GigaCode/Qwen.

Установите [skill/SKILL.md](skill/SKILL.md) способом, поддерживаемым вашей версией GigaCode. Подключение Qwen остаётся на стороне GigaCode.

Для подготовки SDD подключите [risklens-architecture](skills/risklens-architecture/SKILL.md) и [risklens-sdd](skills/risklens-sdd/SKILL.md) тем же способом. Первый навык восстанавливает границы модулей и собирает доказательства. Второй готовит дизайн изменения и связывает требования с проверками. Для запуска передайте формулировку задачи и укажите, какое поведение должно сохраниться.

## Архитектура и зависимости

- Go 1.26, `golang.org/x/tools v0.52.0`: `go/packages`, `go/ast`, `go/types`. Загрузка с тестами, типизация зависимостей, индексация только локальных исходников текущей конфигурации сборки. Нет анализа регулярными выражениями.
- Неизменяемый технический снимок в памяти: символы, определения, использования, вызовы, поля, исходный текст и диагностические сообщения.
- Текстовый индекс в памяти: Unicode-термы, сохранение идентификаторов, CamelCase-компоненты и ранжирование BM25 с бинарной частотой терма. Поиск по кодам правил, строкам и комментариям. Вспомогательные file-фрагменты покрывают package/import и отдельные комментарии вне объявлений.
- Локальные нормализованные embeddings через дочерний Python/ONNX Runtime. Без HTTP-сервера, внешних API и собственного агента. Сервер запускает worker при необходимости, ограничивает время ожидания, завершает его при отмене/выходе.
- Сохраняемый векторный индекс — `vectors.json`, атомарная замена, строгая проверка версии/модели/размерности. Точный cosine scan, фильтрация до рангового слияния. В одном файле векторы, соответствие фрагментов и кэш по подготовленному содержимому. Исчезнувшие фрагменты и неиспользуемые записи удаляются при успешном обновлении.
- RRF с константой 60 объединяет ранги symbol/text/vector. Ответ содержит каналы и ранги; оценки разных шкал напрямую не складываются.
- JSON-RPC `stdio`: 20 MCP-tools, схемы, пагинация, ограничение параллельных запросов, отмена запросов `notifications/cancelled`. Статус и запуск обновления доступны отдельно от долгих операций.

SQLite, графовая БД, ANN-сервис и сервер inference не требуются. Точный векторный scan упрощает поставку и отладку; его стоимость O(N×384), а JSON больше бинарного индекса. Для значительно большего корпуса можно добавить ANN/бинарное хранение после замеров. Технический и текстовый индексы пересоздаются при старте; векторы сохраняются. Прерванная первая векторизация не сохраняет частично вычисленный новый индекс; предыдущий завершённый индекс остаётся на диске.

Обоснование и первичные источники: [ARCHITECTURE.md](docs/ARCHITECTURE.md), [SOURCES.md](docs/SOURCES.md). Ни имена кредитных продуктов, ни структура демонстрационной стратегии в анализатор не зашиты.

## Модель и подготовка входа

Модель `intfloat/multilingual-e5-small`, ревизия `614241f622f53c4eeff9890bdc4f31cfecc418b3`, MIT; ONNX FP32, 384 измерения, контекст 512 токенов. Около 470 MB весов и 17 MB токенизатора (десятичные MB). Нужны свободное место для Python runtime и память для модели; фактический RSS приведён в отчёте.

Сравнивались по официальным карточкам E5-small, BGE-M3 и Qwen3-Embedding-0.6B. Выбран компактный CPU-вариант для MVP. E5 поддерживает русский и другие языки, но не является специально обученной на Go моделью; качество на реальном репозитории неизвестно. Qwen3-Embedding указывает поддержку code retrieval, однако тяжелее; его использование остаётся возможным расширением.

Вход документа: путь пакета, имя, сигнатура, прикреплённые комментарии, код. Функции, методы, типы и пакетные значения разделяются по AST; большие объявления — преимущественно по концам структурных элементов. Для слишком длинной отдельной конструкции используется явное разбиение по строкам/UTF-8 границам. Метаданные сохраняют родительский символ и диапазон. Локальные объявления не дублируют код содержащей функции.

Worker использует **тот же закреплённый tokenizer.json**, добавляет `query: ` или `passage: `, специальные токены, attention-mask mean pooling и L2-нормализацию. Если итоговый вход с метаданными длиннее 512 токенов, все токены обрабатываются окнами, каждое со своим префиксом; среднее окон взвешивается по числу исходных токенов и нормализуется. Молчаливого усечения нет. Параметр batch_size ограничивает число документов в одном запросе worker; в 0.3.0 E5-окна обрабатываются пакетами до 4; Qwen3 принудительно batch=1 из-за проверенной batch-зависимости quantized export. Точные количества токенов и окон сохраняются у векторов в кэше; [реальная проверка](docs/runtime-smoke.json) включает многоконный вход.

`model_key` фиксирует модель, ревизию, FP32, размерность, pooling, префиксы и версию подготовки окон. Разные ключи не смешиваются. При несовместимом сохранённом индексе он не используется; новый строится заново. При несовместимом worker точный поиск остаётся доступным, а векторы переходят в `degraded`.

## Актуальность и ограничения анализа

Перед семантическим запросом и после получения результата проверяется хэш файлов. Анализ читает снимок сохранённых файлов, включая незакоммиченные изменения; `go/packages` получает overlay этого текста. После загрузки хэши проверяются снова. При конфликте выполняется одна повторная попытка, затем возвращается ошибка. Нельзя смешать позиции старого снимка с текстом нового.

При обнаружении изменений запрос возвращает явную ошибку и запускает обновление; опросите `index_status` и повторите запрос. После неудачного обновления старый снимок не выдаётся как текущий. `get_source` читает текст снимка, а не заново прочитанные строки. Несохранённые редакторские буферы не поддерживаются.

Полный повторный анализ модуля допустим и используется. Векторизация выполняется в фоне с кэшированием подготовленного содержимого; exact/text работают после готовности технического индекса. Векторы предыдущего снимка не участвуют в новом поиске. Во время фоновой векторизации прогресс доступен; `vector_done`, `vector_total`, `cache_hits` относятся к текущему снимку.

Идентификаторы пакетных символов включают путь пакета, вид, получателя и имя; поля — тип-владелец и имя. Локальные символы, замыкания и локальные типы зависят от позиции/снимка. Произвольный рефакторинг может менять ID. Варианты пакетов с тестами объединяются по физическим исходникам. `_test.go` доступны; тестовый main из Go build cache не индексируется.

`complete` означает отсутствие диагностированных ошибок загрузки/типизации, **не полноту графа и не бизнес-корректность**. Статические вызовы помечаются `confirmed`; динамические цели могут оставаться `candidates`/`unresolved`. В 0.3.0 ограниченный SSA/VTA уточняет часть вызовов и алиасов (см. ниже). Кандидаты не доказывают достижимость. Вложенные функции имеют собственную идентичность; полного points-to анализа и истории значений нет.

Поля: `read`, `write`, `read_write`, `address`; включая типизированные указатели, promoted fields и ключи структурных литералов. Передача указателя сама по себе записью не считается. Записи через ранее созданный алиас, изменение элемента контейнера как изменение всего поля, присваивание всей структуры, reflection и внешние зависимости не покрываются полной историей. Статический список не задаёт порядок исполнения. Конфигурации GOOS/GOARCH/tags различаются; единого графа для всех вариантов сборки нет.

Внешние зависимости типизируются, но не индексируются целиком. Кэш зависимостей считается подготовленным и неизменяемым во время анализа. Изменение внешнего локального `replace` требует явного `refresh_index`; отслеживание за пределами корня не реализовано. Символические ссылки исходников отвергаются с диагностикой. Скрытые каталоги, vendor, вложенные модули и кэш исключаются. Поддерживаются только явные build flags `-tags=...`; прочие настройки сборки задаются окружением.

## API, лимиты и конфигурация

[API.md](docs/API.md) описывает инструменты и ответы; [mcp-tools.json](docs/mcp-tools.json) — фактические JSON-схемы аргументов, полученные из исполняемого файла. [response.schema.json](docs/response.schema.json) описывает основные формы ответов.

По умолчанию: 20 результатов (максимум 100), исходник до 16 000 байт, контекст по умолчанию 16 000 (максимум 48 000) байт, глубина 0–3, batch 8, 2 CPU-потока worker, до 30 000 файлов и 128 MiB наблюдаемых исходников. Ограничение времени операции/embedding-batch — 300 секунд. Установка модели выполняется отдельно и этим лимитом не ограничивается.

`build_context.budget_bytes` точно ограничивает сериализованный JSON-массив `items` с кодом и метаданными. Внешняя оболочка ответа, диагностика и ограниченный список `omitted` находятся вне этого бюджета. Токены Qwen не вычисляются. Каждое включение имеет причину и источник; пересекающиеся диапазоны исходников повторно не включаются. Для продолжения передайте нужные `omitted` как `chunk_ids`/`symbol_ids` вместе с `index_snapshot`.

Курсоры привязаны к запросу и снимку, а для гибридного поиска — ещё и к готовности векторов/фактически использованным каналам. При несовместимости нужно начать пагинацию заново. Фильтры: префикс пути, точный путь пакета, вид символа, включение тестов. Позиции: строки и UTF-8 **байтовые** столбцы от 1; строки диапазона включительны. Диапазон фрагмента может начинаться внутри строки, при этом `code` содержит только соответствующую часть.

Все настройки: [config.example.json](config.example.json). Параметры `--root` и `--cache` переопределяют конфигурацию. `--schema` и `--version` работают без проекта. Векторный файл и lock доступны только владельцу по Unix permissions; локальный кэш содержит кодовые метаданные и embeddings, поэтому выбирайте подходящее место хранения.

## Обновление, полная переиндексация и диагностика

Обычное обновление: MCP `refresh_index`, затем `index_status`. Изменённые функции пересчитываются, неизменённые embeddings берутся из кэша, исчезнувшие удаляются при публикации нового векторного индекса.

Полная очистка:

```sh
# Сначала остановите MCP-сервер в клиенте.
.venv/bin/python scripts/clear_cache.py --config config.local.json
# Перезапуск заново создаст технический, текстовый и векторный индексы.
./bin/risklens-mcp --config config.local.json --wait-vectors --tool index_status
```

В 0.5.0 `server.lock` — постоянный файл с блокировкой ОС (flock на macOS/Linux, LockFileEx на Windows), а не признак занятости по одному наличию. Блокировка освобождается при закрытии handle или завершении процесса; файл **не удаляйте**, иначе можно создать два разных lock inode и допустить двух владельцев. Одновременно один cache по-прежнему имеет одного владельца. Маркер старой версии мигрирует, только если её PID достоверно не жив; для работающего или недоступного проверке legacy PID запуск блокируется. При откате на старую версию используйте отдельный cache.

`clear_cache.py` теперь вызывает штатный Go-механизм `--clear-cache`, удерживая ту же блокировку ОС во время удаления только vector-файлов. По умолчанию использует go run; можно передать `--binary /absolute/risklens-mcp` версии 0.5+. Сам постоянный lock файл остаётся. Ошибку активного владельца обходить удалением lock нельзя.

- `loading`: дождитесь конца анализа; статус остаётся доступным.
- `fresh=false`: сохраните правки и запросите обновление.
- Ошибки пакетов: проверьте Go в PATH, доступность зависимостей, локальные replace и текущие tags/GOOS/GOARCH. Ошибки не скрываются; частичный индекс имеет `complete=false` и диагностику.
- `vectors=degraded`: проверьте `embedding_error`, пути Python/worker/model, установленные wheels, manifest и hashes. Exact/text доступны. Исправьте окружение и вызовите `refresh_index`.
- Несовместимая ревизия: переустановите закреплённую модель и очистите векторный кэш. Не меняйте один только `model_key`, оставляя прежние веса.
- `cursor snapshot changed` / несовместимый cursor: повторите исходный поиск.
- Конфликт изменения файлов во время анализа: дождитесь окончания сохранений/генерации и повторите `refresh_index`.
- Превышение resource limits: сузьте модуль или осознанно увеличьте соответствующий предел.

## Поля, доказательства и диагностика в 0.2.0

Не конструируйте `symbol_id` из строки вроде `Params.Limit`. Для встроенного поля ID принадлежит объявляющему типу, а не обязательно внешней структуре.

1. Найдите внешний тип через `search_symbols` и скопируйте его настоящий ID.
2. Вызовите `get_symbol`: `meta.fields` содержит `symbol_id`, `access_path`, `promoted`, `definition_indexed` и позицию определения. Число полей ограничено `limit`; `fields_truncated` показывает продолжение.
3. Для полного списка используйте `search_symbols` с `owner_id` этого типа, `kind="field"`, при необходимости `query="Limit"` и пагинацией.
4. Передайте возвращённый канонический ID в `find_field_accesses`. Неоднозначные promoted selectors не объявляются разрешёнными. Внешние определения помечаются `definition_indexed=false`.

Неизвестный ID возвращает `isError=true` и `structuredContent.details`: `code=unknown_symbol_id`, запрошенный ID, hint и ограниченный список реальных candidates. Эти кандидаты не выбираются автоматически. Пустой поиск символа возвращает `meta.exact_match=false` и возможные suggestions; это не доказательство переименования.

`search_code` теперь по умолчанию возвращает один лучший фрагмент на родительский символ, с `other_matching_chunks`. Для прежнего режима фрагментов задайте `distinct_symbols=false`. Фильтр `paths` задаёт несколько допустимых префиксов (OR), `exclude_paths` исключает префиксы; обычные package/path/kind/include_tests продолжают действовать. Для бизнес-запросов ограничивайте продуктовые и общие пакеты явно. Возвращаемое `evidence=semantic_only` означает только векторное совпадение; `lexical_supported` также не доказывает бизнес-смысл. `requires_source_verification=true` требует проверки исходного кода.

`fresh=true` означает совпадение наблюдаемых Go-файлов со снимком. Документы, устаревшие имена, номера строк и утверждения о порядке исполнения оно не проверяет. Перед публикацией ссылки проверяйте существование символа и читайте `get_symbol`/`get_source` с тем же `index_snapshot`. При смене снимка повторите проверку. Пропущенные части длинного символа при сборке контекста теперь явно перечисляются в `omitted`.

В 0.2.0 AST зависимостей целиком не загружается: типы зависимостей по-прежнему разрешаются. Убраны повторные разбиения файла при каждом reference, JSON-сериализация в сравнении связей и квадратичный поиск вложенных объявлений. После загрузки один GC освобождает ненужный граф loader перед векторизацией. Статус показывает version, go_heap_bytes (текущие выделения Go), go_heap_reserved_bytes (зарезервированная куча), go_total_alloc_bytes (накопленные выделения за жизнь процесса), go_gc_cycles и freshness_scope. Эти величины не включают Python/ONNX worker и не равны суммарному RSS.

Для повторения сравнения загрузки: `python scripts/benchmark_loading.py --binary bin/risklens-mcp --baseline /path/to/v0.1.0/risklens-mcp --root /path/to/module --output loading.json`. Это только технический индекс; embeddings отключены. `GOMEMLIMIT` при необходимости задаёт мягкий предел Go runtime, а не жёсткий предел памяти всех процессов.

После обновления пересоберите бинарник и перезапустите MCP-подключение GigaCode, чтобы клиент перечитал tools/list. Для выпуска 0.2.0 проверялось `version=0.2.0`; текущий выпуск должен показывать `version=0.5.0`. Модель и Python переустанавливать не нужно; ключ embeddings не изменён, сохранённые совместимые векторы переиспользуются. Старые локальные ID/курсоры нужно получить заново.

## Новые возможности 0.3.0

### Динамические вызовы и поля

По умолчанию `call_analysis="vta"`: Go SSA + Variable Type Analysis только для исходников модуля, без AST тел внешних зависимостей. Простое присваивание функции переменной может быть разрешено как `ssa_static/confirmed`. Передача callback через параметры, интерфейсные и другие динамические вызовы дают `vta_module` и `flow_candidates`. Старые консервативные interface candidates сохраняются: известные flow targets не доказывают отсутствие внешних целей.

Некоторые записи/чтения через локальные алиасы указателей, параметры, замыкания и возвращаемые указатели теперь находятся как `ssa_alias`, `resolution=candidates`. Это ограниченный поиск возможных полей, не полный points-to анализ и не история конкретного объекта. Ограничения сохраняются для reflection/unsafe, внешних функций, container elements и присваивания всей структуры.

Статус `call_analysis` содержит mode/state/functions/instructions/dynamic_sites/recovered_sites/alias_accesses/error. Лимиты по умолчанию: `max_ssa_functions=20000`, `max_ssa_instructions=300000`; при превышении остаётся AST-навигация и явный skipped_budget. Для прежнего лёгкого режима задайте `call_analysis="ast"`. Ошибка SSA/VTA диагностируется, а не скрывается под видом полного графа. Отмена проверяется между этапами; внутренний вызов VTA сам по себе не предоставляет немедленного прерывания.

`trace_field(symbol_id, entry_symbol_id, depth, include_candidates)` собирает ограниченные чтения/записи по путям вызовов от выбранной функции. По умолчанию кандидаты исключены, глубина 5 (максимум 12). С include_candidates=true возможные пути явно отмечены. `conditions` у связей показывают условия if/else/case/loops из исходников; они не вычисляются. Вывод включает непройденные/внешние вызовы, frontier, лимит элементов и точный байтовый бюджет массива items. Показывается один найденный путь на функцию, а не все возможные трассы.

### Проверка документов и ссылок

- `audit_document(document="docs/notes.md")` читает Markdown внутри корня и проверяет Go-ссылки/диапазоны и inline-имена символов. Пагинация привязана и к Go snapshot, и к document_hash. Это проверка ссылок, не смысловой аудит прозы.
- `verify_evidence(claims=[...])` связывает symbol_id, file, start_line/end_line, expected_text и необязательный source_hash. Hash выдаётся get_symbol.meta.source_hash и get_source.items.source_hash. Результаты различают missing_symbol, missing_file, moved_symbol, invalid_range, moved_text, text_mismatch, source_changed, source_verified и непроверенные привязки.
- Уникальный текст, найденный на другой строке, возвращается в actual как проверяемая подсказка. Автоматической подмены похожего символа и записи в документ нет. GigaCode вносит осмысленные правки штатными средствами после проверки.
- Существование строки без текстового/символьного якоря возвращает range_exists_unbound. Source_verified не доказывает бизнес-утверждение, вызов во время выполнения или порядок этапов.

```sh
.venv/bin/python scripts/audit_document.py --binary bin/risklens-mcp --config config.local.json --document docs/notes.md --output audit.json
```

Поддержаны Markdown Go-links, `path.go:12-20`, `path.go#L12-L20` и inline CamelCase/qualified names. HTTP-ссылки не загружаются. Неподдержанные Go-reference форматы помечаются явно; свободная проза, скриншоты и семантика правил автоматически не проверяются. Документ должен быть UTF-8, не более 1 MiB. Для внешнего документа сначала подготовьте копию внутри модуля либо передавайте структурированные claims.

### Локальные модели и повторное ранжирование

E5 остаётся быстрым профилем по умолчанию. К embedding-входу добавляются механически извлечённые static_facts: виды обращений к полям, указатели в сигнатуре, операторы и места вызовов. Это факты AST/типов, не LLM-аннотации. Добавленные факты меняют content_hash и вызывают пересчёт соответствующих фрагментов.

Есть два дополнительных закреплённых ONNX-профиля:

```sh
.venv/bin/python runtime/setup_model.py --profile qwen3 --output models/qwen3
.venv/bin/python runtime/setup_model.py --profile bge-reranker --output models/reranker
```

Qwen3-Embedding-0.6B: conversion onnx-community, q8, 1024 измерения, last-token pooling, инструкция поиска Go-кода, локальные окна до 2048 токенов. Это более тяжёлый альтернативный профиль; его превосходство не предполагается. Для выбора укажите его model-dir в configure.py; dimension и model_key прочитаются из manifest. Кэши разных моделей несовместимы, используйте отдельный cache.

BGE-reranker-v2-m3: дополнительный локальный cross-encoder. Он оценивает пары запрос/фрагмент и переупорядочивает только первые N hybrid-кандидатов. Это не генератор и не отдельный агент. Включение:

```sh
.venv/bin/python scripts/configure.py --root /path/to/module --python .venv/bin/python --model-dir models/e5-small --reranker-model-dir models/reranker --output config.local.json
```

Настройки: reranker_command, reranker_model_key, rerank_candidates (по умолчанию 30, максимум 100). На CPU это может быть заметно медленнее обычного поиска; измерения и ограничения приведены в отчёте 0.3.0. Для отдельного запроса `rerank=false` отключает стадию. При недоступном reranker остаётся RRF с предупреждением. Баллы rerank_score — относительное ранжирование, не вероятность бизнес-корректности. Проверка на демонстрационном модуле: `python scripts/reranker_smoke.py --binary bin/risklens-mcp --config /absolute/reranker-config.json --output /tmp/reranker-smoke.json`. Кэш до 2048 пар query/content/model ускоряет повторы; он не смешивает изменённое содержимое или модели.

Worker действительно обрабатывает окна пакетами (по умолчанию до 4 окон в ONNX forward); `--batch-size` ограничивает ресурс. E5 использует masked mean; Qwen — last token, принудительно batch=1. Первоначальная batch4-проверка Qwen отвергнута, ключ кэша изменён, а batch1 повторно проверен. Все файлы проверяются потоковым SHA256 по закреплённым manifest/lock. Переполненные embedding-входы покрываются окнами без усечения. Reranker ограничен 2048 токенами пары; при превышении возвращает ошибку и поиск сохраняет RRF, без молчаливого обрезания.


## Работа с пакетами и контрактами (0.5.0)

Для нескольких независимых чтений/поисков используйте `batch_tools`: до 20 calls на одном immutable Go snapshot, две полные freshness-проверки на пакет. При изменении исходников результаты пакета отклоняются. У каждого элемента свой is_error; доверяйте свежести только внешнего ответа. Byte-budget items — 512 KiB; при truncated используйте remaining_from, либо выполните слишком большой элемент отдельно.

```json
{"calls":[{"tool":"get_source","arguments":{"file":"main.go","end_line":-1}},{"tool":"search_symbols","arguments":{"query":"Limit","limit":10}}]}
```

Для имён контракта используйте `resolve_reference` с query, namespace=go|json|auto и при необходимости owner_id. Пример Go-пути: query="Request.Rules.Age.Min", namespace="go". Пример JSON-алиаса объявления: query="pti_max", namespace="json". Регистр сохраняется; несколько совпадений остаются кандидатами. owner_id — ID типа либо непрозрачный target_scope_id из meta.fields; последний может обозначать анонимную вложенную структуру. JSON leaf-алиасы не доказывают полный wire path/поведение encoding/json. Никаких выводов о том же runtime-объекте или бизнес-применимости.

В audit_document добавлены contract_name_verified/field_path_verified и диагностические unbound_path/unrecognized_token. candidate_signature_groups группирует форму кандидатов, но одинаковая сигнатура не снимает смысловую неоднозначность. Проверяйте field_scope_truncated; группировка и binding не являются semantic verification.

`get_callees.meta.call_coverage` показывает локальные call sites, candidate/unresolved/external и примеры границ. Пустая выдача callers/references не доказывает отсутствие поведения.

Search meta содержит reranker status/configured/attempted/executed/model_key/scored_items/cache_hits/reranked_items и причины fallback. Выполненная стадия и cache_hit отличаются от disabled/not_applicable/empty. Для обязательного эксперимента используйте `scripts/evaluate.py --require-reranker`: он отклоняет ненастроенный или неотработавший reranker. Поиск без обязательного флага сохраняет безопасный fallback. Query embedding cache ограничен 256 записями процесса, привязан к model/preparation key и размерности; meta.query_embedding_cache показывает hit/executed. Полный индекс при этом всё равно проходит strict freshness.

## Карта Go-проекта и поиск по пакетам

При индексации RiskLens собирает карточки пакетов из активной Go-сборки. В карточке есть короткий GoDoc с позицией в файле, число файлов и до 12 экспортируемых имён. Карта показывает импорты, `main`/`init`, объявления интерфейсов и реализации. Вызов `project_map` без `node_id` возвращает карточки пакетов. С ID узла можно раскрыть небольшой подграф.

В лексическом и гибридном поиске совпадение нескольких слов запроса с GoDoc добавляет сигнал `package_context`. Он может поднять подходящее объявление внутри пакета и добавить исходный GoDoc в выдачу. Для сравнения задайте `package_context=false`. Если пакет уже известен, передайте его полный путь в `package`. Тогда поиск оценивает кандидатов этого пакета и показывает объём работы в `meta.search_scope`.

Для навигации и поиска по готовому снимку передайте `freshness="snapshot"` и `index_snapshot` из карты в `search_code`, `build_context`, `get_symbol` или `get_source`. Это устраняет обход диска на запрос. Такой ответ имеет `fresh=false`. После изменения исходников используйте строгий режим или `batch_tools`.

Для разбора сборки набора передайте ID Go-функции в `rule_membership`. Пилот показывает явно возвращаемые элементы среза, исходные позиции, guards и неизвестные ветки. Для оценки полноты поиска можно задать в запросе к `scripts/evaluate.py` поле `required_evidence` со списком обязательных ID. Отчёт покажет долю найденных элементов и перечислит пропущенные ID.
