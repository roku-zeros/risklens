# RiskLens

Локальный инструмент анализа Go-кода для GigaCode: типизированная навигация, связи вызовов и обращений к полям, текстовый и векторный поиск, сборка контекста. MCP `stdio` — интерфейс доступа к анализатору. Сервер не содержит LLM-агента, не генерирует аннотации и не редактирует исследуемый код.

## Быстрый старт

Нужны Go **1.26+** в `PATH` и Python **3.10–3.12** с подходящими CPU wheels. Фактически проверены Go 1.26.6, Python 3.11.2, macOS 14.1.1 arm64. Сборки Linux amd64 и Windows amd64 проверяются отдельно; запуск на них не заявляется проверенным. Подробности — [отчёт](docs/REPORT.md).

Из корня `risklens` выполните установочный шаг с интернетом:

```sh
go mod download
go build -trimpath -o bin/risklens-mcp ./cmd/risklens-mcp
python3.11 -m venv .venv
.venv/bin/python -m pip install -r runtime/requirements-lock.txt
.venv/bin/python runtime/setup_model.py --output models/e5-small
.venv/bin/python scripts/configure.py \
  --root examples/strategy \
  --python .venv/bin/python \
  --model-dir models/e5-small \
  --output config.local.json
```

`configure.py` сохраняет абсолютные пути. Для своего репозитория замените `--root`. Корень должен содержать единственный анализируемый `go.mod`; вложенные модули пропускаются. Используйте отдельный cache для каждого проекта/процесса.

Windows PowerShell:

```powershell
go mod download
go build -trimpath -o bin/risklens-mcp.exe ./cmd/risklens-mcp
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r runtime/requirements-lock.txt
.venv\Scripts\python.exe runtime/setup_model.py --output models/e5-small
.venv\Scripts\python.exe scripts/configure.py --root examples/strategy --python .venv/Scripts/python.exe --model-dir models/e5-small --output config.local.json
```

Подготовьте зависимости **исследуемого** проекта отдельным установочным шагом `go mod download` в нём. Анализатор не загружает зависимости и toolchain из интернета. Он использует `GOPROXY=off`, `GONOPROXY=none`, `GOSUMDB=off`, `GOVCS=*:off`, `GOTOOLCHAIN=local`, `GOWORK=off` и `-mod=readonly`; `go.mod`/`go.sum` не меняет. Локальные `replace` должны быть доступны на диске; их исходники не индексируются, если находятся за пределами выбранного модуля.

Штатная работа после подготовки окружения — офлайн:

```sh
./bin/risklens-mcp --config config.local.json
```

Это MCP-сервер, ожидающий JSON-RPC на stdin. Отсутствие обычного текста в терминале нормально. Протокольный stdout отделён от диагностического stderr. Для проверки без MCP-клиента:

```sh
./bin/risklens-mcp --config config.local.json --wait-vectors --tool index_status
./bin/risklens-mcp --config config.local.json --tool search_symbols --args '{"query":"Calculate","limit":10}'
./bin/risklens-mcp --config config.local.json --wait-vectors --tool search_code --args '{"query":"льготный период обучения","limit":5}'
```

Перед одноразовой проверкой остановите постоянный сервер либо укажите отдельный `--cache`. Одноразовый запуск заново загружает Go-модуль. Для постоянной работы используйте один MCP-процесс. `--wait-vectors` обязателен в одноразовом запуске, если нужны готовые векторы. Без настройки embeddings можно использовать `--root /path/to/module`: точная навигация и текстовый поиск работают, статус сообщает `vectors=degraded`.

## Подключение GigaCode

Зарегистрируйте сервер с именем `risklens-mcp`, транспортом `stdio`, абсолютным путём к исполняемому файлу и аргументами:

```text
/absolute/path/to/risklens/bin/risklens-mcp --config /absolute/path/to/risklens/config.local.json
```

На Windows имя файла — `risklens-mcp.exe`. У клиентского процесса должны быть Go 1.26+ в PATH и доступ к подготовленному модульному кэшу. Активную версию внешней команды Go показывает `environment.GOVERSION`; `environment.toolchain` — версия сборки самого сервера.

[Шаблон подключения](docs/gigacode-connection.template.json) **концептуальный, его ключи не являются проверенной схемой конфигурации GigaCode**. Версия GigaCode в окружении разработки отсутствовала. Перенесите command/args в документированный вашей версией формат. Интероперабельность `stdio` проверена официальным Python SDK `mcp==1.26.0`, но это не проверка GigaCode/Qwen.

Установите [skill/SKILL.md](skill/SKILL.md) способом, поддерживаемым вашей версией GigaCode. Подключение Qwen остаётся на стороне GigaCode.

## Архитектура и зависимости

- Go 1.26, `golang.org/x/tools v0.52.0`: `go/packages`, `go/ast`, `go/types`. Загрузка с тестами, типизация зависимостей, индексация только локальных исходников текущей конфигурации сборки. Нет анализа регулярными выражениями.
- Неизменяемый технический снимок в памяти: символы, определения, использования, вызовы, поля, исходный текст и диагностические сообщения.
- Текстовый индекс в памяти: Unicode-термы, сохранение идентификаторов, CamelCase-компоненты и ранжирование BM25 с бинарной частотой терма. Поиск по кодам правил, строкам и комментариям. Вспомогательные file-фрагменты покрывают package/import и отдельные комментарии вне объявлений.
- Локальные нормализованные embeddings через дочерний Python/ONNX Runtime. Без HTTP-сервера, внешних API и собственного агента. Сервер запускает worker при необходимости, ограничивает время ожидания, завершает его при отмене/выходе.
- Сохраняемый векторный индекс — `vectors.json`, атомарная замена, строгая проверка версии/модели/размерности. Точный cosine scan, фильтрация до рангового слияния. В одном файле векторы, соответствие фрагментов и кэш по подготовленному содержимому. Исчезнувшие фрагменты и неиспользуемые записи удаляются при успешном обновлении.
- RRF с константой 60 объединяет ранги symbol/text/vector. Ответ содержит каналы и ранги; оценки разных шкал напрямую не складываются.
- JSON-RPC `stdio`: 12 MCP-tools, схемы, пагинация, ограничение параллельных запросов, отмена запросов `notifications/cancelled`. Статус и запуск обновления доступны отдельно от долгих операций.

SQLite, графовая БД, ANN-сервис и сервер inference не требуются. Точный векторный scan упрощает поставку и отладку; его стоимость O(N×384), а JSON больше бинарного индекса. Для значительно большего корпуса можно добавить ANN/бинарное хранение после замеров. Технический и текстовый индексы пересоздаются при старте; векторы сохраняются. Прерванная первая векторизация не сохраняет частично вычисленный новый индекс; предыдущий завершённый индекс остаётся на диске.

Обоснование и первичные источники: [ARCHITECTURE.md](docs/ARCHITECTURE.md), [SOURCES.md](docs/SOURCES.md). Ни имена кредитных продуктов, ни структура демонстрационной стратегии в анализатор не зашиты.

## Модель и подготовка входа

Модель `intfloat/multilingual-e5-small`, ревизия `614241f622f53c4eeff9890bdc4f31cfecc418b3`, MIT; ONNX FP32, 384 измерения, контекст 512 токенов. Около 470 MB весов и 17 MB токенизатора (десятичные MB). Нужны свободное место для Python runtime и память для модели; фактический RSS приведён в отчёте.

Сравнивались по официальным карточкам E5-small, BGE-M3 и Qwen3-Embedding-0.6B. Выбран компактный CPU-вариант для MVP. E5 поддерживает русский и другие языки, но не является специально обученной на Go моделью; качество на реальном репозитории неизвестно. Qwen3-Embedding указывает поддержку code retrieval, однако тяжелее; его использование остаётся возможным расширением.

Вход документа: путь пакета, имя, сигнатура, прикреплённые комментарии, код. Функции, методы, типы и пакетные значения разделяются по AST; большие объявления — преимущественно по концам структурных элементов. Для слишком длинной отдельной конструкции используется явное разбиение по строкам/UTF-8 границам. Метаданные сохраняют родительский символ и диапазон. Локальные объявления не дублируют код содержащей функции.

Worker использует **тот же закреплённый tokenizer.json**, добавляет `query: ` или `passage: `, специальные токены, attention-mask mean pooling и L2-нормализацию. Если итоговый вход с метаданными длиннее 512 токенов, все токены обрабатываются окнами, каждое со своим префиксом; среднее окон взвешивается по числу исходных токенов и нормализуется. Молчаливого усечения нет. Параметр batch_size ограничивает число документов в одном запросе worker; ONNX forward выполняется последовательно по окнам с фактическим batch=1. Точные количества токенов и окон сохраняются у векторов в кэше; [реальная проверка](docs/runtime-smoke.json) включает многоконный вход.

`model_key` фиксирует модель, ревизию, FP32, размерность, pooling, префиксы и версию подготовки окон. Разные ключи не смешиваются. При несовместимом сохранённом индексе он не используется; новый строится заново. При несовместимом worker точный поиск остаётся доступным, а векторы переходят в `degraded`.

## Актуальность и ограничения анализа

Перед семантическим запросом и после получения результата проверяется хэш файлов. Анализ читает снимок сохранённых файлов, включая незакоммиченные изменения; `go/packages` получает overlay этого текста. После загрузки хэши проверяются снова. При конфликте выполняется одна повторная попытка, затем возвращается ошибка. Нельзя смешать позиции старого снимка с текстом нового.

При обнаружении изменений запрос возвращает явную ошибку и запускает обновление; опросите `index_status` и повторите запрос. После неудачного обновления старый снимок не выдаётся как текущий. `get_source` читает текст снимка, а не заново прочитанные строки. Несохранённые редакторские буферы не поддерживаются.

Полный повторный анализ модуля допустим и используется. Векторизация выполняется в фоне с кэшированием подготовленного содержимого; exact/text работают после готовности технического индекса. Векторы предыдущего снимка не участвуют в новом поиске. Во время фоновой векторизации прогресс доступен; `vector_done`, `vector_total`, `cache_hits` относятся к текущему снимку.

Идентификаторы пакетных символов включают путь пакета, вид, получателя и имя; поля — тип-владелец и имя. Локальные символы, замыкания и локальные типы зависят от позиции/снимка. Произвольный рефакторинг может менять ID. Варианты пакетов с тестами объединяются по физическим исходникам. `_test.go` доступны; тестовый main из Go build cache не индексируется.

`complete` означает отсутствие диагностированных ошибок загрузки/типизации, **не полноту графа и не бизнес-корректность**. Статические вызовы помечаются `confirmed`; интерфейсные цели — `candidates` среди известных реализаций модуля, переменные функций — `unresolved`. Кандидаты не доказывают достижимость. Вложенные функции имеют собственную идентичность. Полноценного SSA/межпроцедурного анализа нет.

Поля: `read`, `write`, `read_write`, `address`; включая типизированные указатели, promoted fields и ключи структурных литералов. Передача указателя сама по себе записью не считается. Записи через ранее созданный алиас, изменение элемента контейнера как изменение всего поля, присваивание всей структуры, reflection и внешние зависимости не покрываются полной историей. Статический список не задаёт порядок исполнения. Конфигурации GOOS/GOARCH/tags различаются; единого графа для всех вариантов сборки нет.

Внешние зависимости типизируются, но не индексируются целиком. Кэш зависимостей считается подготовленным и неизменяемым во время анализа. Изменение внешнего локального `replace` требует явного `refresh_index`; отслеживание за пределами корня не реализовано. Символические ссылки исходников отвергаются с диагностикой. Скрытые каталоги, vendor, вложенные модули и кэш исключаются. Поддерживаются только явные build flags `-tags=...`; прочие настройки сборки задаются окружением.

## API, лимиты и конфигурация

[API.md](docs/API.md) описывает инструменты и ответы; [mcp-tools.json](docs/mcp-tools.json) — фактические JSON-схемы аргументов, полученные из исполняемого файла. [response.schema.json](docs/response.schema.json) описывает основные формы ответов.

По умолчанию: 20 результатов (максимум 100), исходник до 16 000 байт, контекст по умолчанию 16 000 (максимум 48 000) байт, глубина 0–3, batch 8, 2 CPU-потока worker, до 30 000 файлов и 128 MiB наблюдаемых исходников. Ограничение времени операции/embedding-batch — 300 секунд. Установка модели выполняется отдельно и этим лимитом не ограничивается.

`build_context.budget_bytes` точно ограничивает сериализованный JSON-массив `items` с кодом и метаданными. Внешняя оболочка ответа, диагностика и ограниченный список `omitted` находятся вне этого бюджета. Токены Qwen не вычисляются. Каждое включение имеет причину и источник; пересекающиеся диапазоны исходников повторно не включаются. Для продолжения передайте нужные `omitted` как `chunk_ids`/`symbol_ids` вместе с `index_snapshot`.

Курсоры привязаны к запросу и снимку, а для гибридного поиска — ещё и к готовности векторов/фактически использованным каналам. При несовместимости нужно начать пагинацию заново. Фильтры: префикс пути, точный путь пакета, вид символа, включение тестов. Позиции: строки и UTF-8 **байтовые** столбцы от 1; строки диапазона включительны. Диапазон фрагмента может начинаться внутри строки, при этом `code` содержит только соответствующую часть.

Все настройки: [config.example.json](config.example.json). Параметры `--root` и `--cache` переопределяют конфигурацию. `--schema` и `--version` работают без проекта. Векторный файл и lock доступны только владельцу по Unix permissions; локальный кэш содержит кодовые метаданные и embeddings, поэтому выбирайте подходящее место хранения.

## Обновление, полная переиндексация и диагностика

Обычное обновление: MCP `refresh_index`, затем `index_status`. Изменённые функции пересчитываются, неизменённые embeddings берутся из кэша, исчезнувшие удаляются при публикации нового векторного индекса.

Полная очистка:

```sh
# Сначала остановите MCP-сервер в клиенте.
.venv/bin/python scripts/clear_cache.py --config config.local.json
# Перезапуск заново создаст технический, текстовый и векторный индексы.
./bin/risklens-mcp --config config.local.json --wait-vectors --tool index_status
```

`clear_cache.py` удаляет только известные файлы RiskLens и отказывается работать при `server.lock`. После аварийного завершения проверьте PID в lock и удалите **только устаревший** lock вручную. Одновременное использование одного cache двумя процессами запрещено. Обычный EOF, interrupt и terminate завершают worker; жёсткое завершение процесса средствами ОС может потребовать очистки lock и оставшегося дочернего процесса.

- `loading`: дождитесь конца анализа; статус остаётся доступным.
- `fresh=false`: сохраните правки и запросите обновление.
- Ошибки пакетов: проверьте Go в PATH, доступность зависимостей, локальные replace и текущие tags/GOOS/GOARCH. Ошибки не скрываются; частичный индекс имеет `complete=false` и диагностику.
- `vectors=degraded`: проверьте `embedding_error`, пути Python/worker/model, установленные wheels, manifest и hashes. Exact/text доступны. Исправьте окружение и вызовите `refresh_index`.
- Несовместимая ревизия: переустановите закреплённую модель и очистите векторный кэш. Не меняйте один только `model_key`, оставляя прежние веса.
- `cursor snapshot changed` / несовместимый cursor: повторите исходный поиск.
- Конфликт изменения файлов во время анализа: дождитесь окончания сохранений/генерации и повторите `refresh_index`.
- Превышение resource limits: сузьте модуль или осознанно увеличьте соответствующий предел.

## Проверки и повторяемые измерения

```sh
go test ./...
go test -race ./...
go vet ./...
(cd examples/strategy && go test ./...)
.venv/bin/python scripts/runtime_smoke.py --config config.local.json
.venv/bin/python scripts/evaluate.py --binary bin/risklens-mcp --config config.local.json --queries examples/queries.json --output benchmark.json
# Необязательная независимая MCP-проверка:
.venv/bin/python -m pip install mcp==1.26.0
.venv/bin/python scripts/sdk_smoke.py --binary bin/risklens-mcp --config config.local.json
```

Для рабочего репозитория создайте отдельную конфигурацию и свой JSON-набор запросов в формате `examples/queries.json` с ожидаемыми `symbol_id`. `evaluate.py` копирует исходники во временный каталог и меняет одну функцию **только в копии**; оставьте свободное место для копии. Он измеряет первую индексацию, запуск с кэшем, обновление, первый и прогретый поиск, hit@5/10, размер векторного файла и sampled RSS дерева процессов. RSS собирается через ps; при недоступности этого средства (например, Windows) значение null, используйте системный профилировщик. Предполагаются обычные функции с телом; для нестандартного корпуса проверьте выбранную автоматическую мутацию. Большой корпус требует достаточного timeout клиента.

На демонстрационном модуле оценки не доказывают качество на кредитной стратегии пользователя. Фактические числа, неудачные запросы, оборудование, ограничения и платформенные проверки — в [docs/REPORT.md](docs/REPORT.md). Полная трассировка требований — [docs/TRACEABILITY.md](docs/TRACEABILITY.md).
