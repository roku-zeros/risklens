# RiskLens 0.3.0 — flow analysis, source evidence and retrieval profiles

Дата: 6 ноября 2026 года. Рабочий репозиторий пользователя недоступен; проверка проведена на синтетических модулях и демонстрации. Частный документ по фотографии не переписывался.

## Реализовано

- SSA + Variable Type Analysis для тел функций модуля. Локальные значения-функции могут получать точную цель, параметры/callback/interface — известные flow candidates. Анализ имеет бюджеты и AST fallback; external/reflection/unsafe не объявляются покрытыми.
- Ограниченное обнаружение чтений/записей через алиасы указателей, параметры, замыкания и возвращаемые указатели. Такие обращения помечаются кандидатами, не доказанной историей одного объекта.
- trace_field от конкретной точки входа, с call_path, различием подтверждённых/возможных связей, синтаксическими условиями ветвей, frontier и неизвестными границами. Порядок строк/вызовов не выдается за порядок исполнения.
- audit_document проверяет ссылки и inline-имена по всему Markdown с пагинацией и document_hash. verify_evidence связывает canonical ID, файл, строки, ожидаемый текст и hash. Missing/moved/ambiguous/stale/unbound различаются. Исправления не угадываются и автоматически не применяются.
- Retrieval-вход включает механические static_facts AST/типов. E5 обрабатывает окна настоящими пакетами. Есть альтернативный Qwen3 q8-профиль и дополнительный multilingual cross-encoder BGE reranker. Новые модели загружаются только отдельной установкой и не становятся обязательными для exact/text поиска.
- Reranker применяется только к hybrid-кандидатам, имеет ограничение количества и контекста, явный fallback и bounded pair-score cache. Его оценки не являются доказательством бизнес-корректности.

## Проверка моделей

E5 остаётся профилем по умолчанию. Прежде чем менять конфигурацию рабочего репозитория, необходимо измерить свои запросы и ожидаемые символы.

Первоначальная Qwen3 batch4-конверсия не прошла проверку batch equivalence (cosines около 0.93). Этот эксперимент отвергнут; данные сохранены в experiments/qwen3-batch4-rejected.json и не используются как подтверждённое качество выпуска. Исправленный профиль принудительно batch1, имеет новый model_key и прошёл повторную проверку с cosine 1.0 при requested batch 1/4. Старые qwen-векторы с другим ключом не смешиваются.

E5 batch1/4 проверен отдельно. Веса всех профилей, токенизаторы и конфигурации закреплены по revision/SHA256; готовый worker работает локально, без сетевых запросов и без генерации текста.

На одном синтетическом корпусе (9 Go-файлов, 488 строк, 12 запросов) получены следующие Hit@k — число запросов, где найден хотя бы один ожидаемый символ:

| Профиль | Vector Hit@5 / @10 | Hybrid Hit@5 / @10 | Время hybrid |
|---|---:|---:|---:|
| E5 | 10/12 / 11/12 | 10/12 / 11/12 | медиана повторных запросов 14.9 мс |
| Qwen3 q8 batch1 | 5/12 / 11/12 | 10/12 / 11/12 | медиана первых запросов 205.4 мс |
| E5 + BGE reranker (30 кандидатов) | 10/12 / 11/12 | 12/12 / 12/12 | первый запрос 25.6 с, повтор с кэшем 17.1 мс |

Для E5+BGE проведены два выполнения каждого запроса. Улучшение Hit@k относится только к этому набору. Повтор использует pair-score cache; для нового запроса следует ожидать inference latency. Во время части замера параллельно выполнялись проверки, поэтому время ориентировочное. RSS дерева процессов получить не удалось из-за ограничений ps; JSON содержит null, а не оценку памяти.

Qwen3 измерен по одному выполнению каждого запроса: поле `warm_median_ms` в его JSON использует fallback на первое выполнение и не подтверждает warm latency. Более крупная модель здесь не улучшила hybrid Hit@k, а vector Hit@5 ухудшился. Сравнение не заменяет оценку на рабочем репозитории.

Реальный BGE reranker проверен отдельно с 5 кандидатами: первый вызов 12577 мс, повтор с pair-score cache 37 мс (`reranker-smoke-v0.3.0.json`). Это один запрос при параллельной нагрузке, не latency SLA; результаты повторов совпали и содержали rerank_score. CPU-задержка делает стадию необязательной.

Результаты качества и времени находятся в отдельных JSON: e5-v0.3.0.json, qwen3-v0.3.0.json, rerank-v0.3.0.json. Числа и допуски этих проверок относятся к маленькому демонстрационному корпусу. Лицензии/источники и setup-команды приведены в README и SOURCES.md.

## Проверки и ограничения

Проверяются регрессии VTA callbacks, SSA-static function values, AST fallback, pointer aliases, product guards, bounded field trace, source hashes, moved anchors, missing/ambiguous references, смена документа во время пагинации, выход за root и недоступный reranker. Пройдены `go test -race ./...`, `go vet ./...`, интеграция официальным MCP SDK с 15 tools и демонстрация всех инструментов с реальными E5 embeddings без изменения исходников. JSON-схемы проверены на демонстрационных ответах. Linux/amd64 и Windows/amd64 проходят cross-build; запуск проверен на macOS/arm64.

Статический анализ остаётся приближённым: не восстанавливает полный points-to граф, реальную историю значений, внешние побочные эффекты и все пути исполнения. Документный аудит проверяет исходные привязки, а не истинность свободной прозы. Более крупная модель или reranker не устраняют эту границу. GigaCode и рабочая стратегия недоступны при разработке.

После обновления пересоберите бинарник, перезапустите MCP-подключение и проверьте project_status.version=0.3.0. Для больших проектов отслеживайте call_analysis.state; при необходимости уменьшите budgets или выберите call_analysis=ast. Embedding-подготовка со static_facts изменяет content_hash, поэтому часть векторов пересчитается. Остальные совместимые записи переиспользуются.

## Запуск из исходников

Добавлен `docs/gigacode-go-run.template.json`: stdio-запуск через `go -C /path/to/risklens run ./cmd/risklens-mcp --config /path/to/config.json`. Официальный MCP SDK прошёл проверку всех 15 инструментов при этом способе запуска (`docs/sdk-go-run-v0.3.0.json`). Отдельный демон и готовый бинарник не требуются. Формат настроек конкретной версии GigaCode остаётся непроверенным.
