# RiskLens 0.4.0 — исправления API и диагностика запросов

6 ноября 2026. Первая серия исправлений по внешнему прогону. Рабочий модуль и исходный driver.log не доступны; результаты на нём не воспроизведены. Материалы backlog: [разбор](RUN-REVIEW-2026-11-06.md), [что измерять](RUN-FEEDBACK-REQUEST.md).

## Изменения

- **Чтение исходников:** `get_source` возвращает total_lines/returned_lines/eof/range_clamped, принимает `end_line=-1`. Запрошенный конец за EOF обрезается. Ошибочный start_line/обратный диапазон отвергаются с total_lines и подсказкой. Сохраняется byte-limit; meta.next_line позволяет продолжить, а слишком длинная строка имеет явное объяснение невозможности продвижения.
- **Inventory:** новый `list_files` со списком индексируемых Go/mod/sum файлов, путями, длиной, байтами и hash. Есть фильтры путей/тестов, страницы и snapshot. Это не список всех ресурсов репозитория. Всего 16 MCP tools.
- **Ошибки аргументов:** строгая рекурсивная валидация вложенных claims, типов, enum и размеров; JSON-RPC error.data содержит code/field/allowed_fields/expected/example_arguments/hint. Runtime-ошибки пути/диапазона/limit имеют структурированные details. Неверные имена не принимаются молча.
- **Полнота выдачи:** meta.total_results/returned_results/offset/has_more у списков, results_complete/effective_limit/continuation. Обрезанные поля структуры теперь отмечаются также верхним truncated. Cursor допускает добавление index_snapshot из первой страницы: идентичность снимка проверяется отдельно, фильтры по-прежнему связаны с курсором.
- **Диагностика:** timings_ms для полного серверного запроса, freshness (с вложенными read_hash/walk_metadata), symbol/text, query embedding, vector scan/sort, fusion и rerank по выполненным этапам. Freshness_scans/file_reads/source_bytes объясняют масштаб проверки. Status.last_refresh хранит отдельный замер последнего завершённого refresh с load_analysis. Время сериализации, запуск процесса, клиент и фоновые embeddings не выдаются за эти фазы.
- **Стоимость проверки актуальности:** потоковое хеширование с переиспользуемым буфером и отменой во время чтения заменяет временное сохранение всех исходников. Полное чтение содержимого до/после запроса остаётся: доверие только timestamp не используется. После ошибки дополнительного дискового прохода ради status больше нет; error fresh=false/freshness_checked=false не доказывает устарелость, а означает отсутствие повторной проверки после ошибки.
- **Инструкция агента:** краткая памятка о 40 строках, EOF, root-relative paths, claims/document, лимитах, продолжении и разборе ошибок добавлена в skill.

## Как повторить измерение задержек

После обновления перезапустите MCP-клиент: version=0.4.0, tools/list содержит 16 tools. Предпочтительный запуск через go run сохранён. Для standalone benchmark можно собрать бинарник и записать запросы в одном постоянном процессе:

```sh
go build -trimpath -o bin/risklens-mcp ./cmd/risklens-mcp
.venv/bin/python scripts/profile_requests.py \
  --binary bin/risklens-mcp --config /absolute/config.json \
  --file relative/path/to/file.go --query Limit \
  --repeats 5 --wait-vectors --output /tmp/risklens-profile.json
```

Флаг wait-vectors нужен для сравнения retrieval после окончания фоновой векторизации; без него доступна проверка lexical/navigation, но надо учитывать fallback и фоновую нагрузку. Query/file замените на свои. Скрипт сохраняет raw responses, серверные фазы, client duration, ошибки и промежуточный JSON. Response_bytes — размер повторной сериализации, не точный wire size и не токены. Малое число повторов не устанавливает p95.

## Проверки

Результаты текущего выпуска: [официальный SDK и go run](sdk-go-run-v0.4.0.json), [все инструменты с E5](demo-v0.4.0.json), [профиль 35 запросов](request-profile-v0.4.0.json), [микрозамер аллокаций](freshness-allocation-v0.4.0.log).

Пройдены `go test -race ./...`, `go vet ./...`, проверка официальным SDK через go run, проверка схем на 21 demo-ответе и 35 profile-ответах. Проверка запуска выполнена на macOS/arm64; Linux/amd64 и Windows/amd64 проверены cross-build.

Регрессии покрывают EOF с/без завершающего перевода строки и пустой файл; лимит байт и слишком длинную строку; 106 inventory-элементов на двух страницах без потерь/повторов; добавление snapshot к cursor; обрезку списка полей; строгое вложенное claims validation и JSON-RPC recovery; отсутствие добавочного scan на ошибке; одинаковые fingerprint потокового/полного чтения; лимиты/отмену; same-size edit с восстановленным mtime. Обычный source/поисковый запрос сохраняет два freshness scan, статус — один.

Локальный микрозамер дал 9 108 328 B/op для удержания исходников и 170 926 B/op для потокового fingerprint (примерно в 53 раза меньше временных аллокаций). Это не сравнение peak RSS и не измерение скорости в рабочем контуре.

Микрозамер сравнивает две ветки текущей реализации на 64 синтетических файлах по ~128 KiB (в сумме ~8 MiB). Retain_source_contents соответствует операции загрузки с удержанием исходников, stream_fingerprint_only — проверке актуальности. B/op — суммарные Go-аллокации на scan, не peak RSS процесса. Время — локальный микрозамер на macOS/Apple M1, не подтверждение ускорения рабочего модуля.

Профиль demo показывает разницу чтения/статуса и model inference на маленьком модуле. Первый vector-запрос включает cold worker startup: его нельзя скрывать за медианой повторов. Эти цифры не подтверждают устранение внешних 8 секунд. Теперь фазы можно измерить тем же скриптом на рабочем модуле.
