# RiskLens 0.2.0 — исправления по результатам эксплуатации

Дата: 6 ноября 2026 года.

## Что подтверждено и исправлено

1. **Навигация по встроенным полям.** Типы теперь возвращают канонические ID прямых и promoted fields в `get_symbol.meta.fields`. `search_symbols.owner_id` обеспечивает фильтрацию и пагинацию этих полей. Путь доступа (`access_path`) отделён от владельца объявления. Неоднозначные selectors исключаются; затенение, указатели, generics и переходы между пакетами проверены тестами. У внешних неиндексируемых определений нет ложной локальной позиции.
2. **Восстановление после неизвестного ID.** Раньше ответ содержал только `unknown symbol_id`. Теперь tool error имеет structuredContent.details с code, запрошенным ID, подсказкой и реальными кандидатами. Неправильно составленный ID автоматически не разрешается. Кандидаты не являются доказанным переименованием.
3. **Расход памяти и время загрузки.** Удалён NeedDeps при загрузке AST: зависимости по-прежнему разрешаются для типов, AST и тела всех зависимостей не загружаются целиком. Короткий контекст строки извлекается по заранее вычисленным началам строк, без strings.Split всего файла для каждого reference. Сортировка связей больше не сериализует их в JSON на каждом сравнении. Проверка вложенных объявлений линейна по отсортированным диапазонам; chunks группируются по файлу. Однократный GC после загрузки освобождает временный граф loader перед векторизацией.
4. **Управление поисковым контекстом.** По умолчанию один лучший фрагмент на родительский символ; `distinct_symbols=false` сохраняет прежнюю выдачу chunks. Дополнительные paths/exclude_paths позволяют ограничить продуктовые и общие пакеты. Добавлены фильтрация общих стоп-слов, evidence и requires_source_verification. Сходство не становится доказательством бизнес-принадлежности.
5. **Проверяемость и продолжение.** Статус показывает версию и freshness_scope. Fresh=true проверяет наблюдаемые Go-файлы, а не актуальность документов или порядок выполнения. Пропущенные части найденной длинной функции перечисляются в omitted. Skill дополнен проверкой ID, существования декларации, текущих строк, product scope, и явным разделением статических/возможных связей.

## Сравнение загрузки технического индекса

Синтетический модуль: 321 Go-файл, 10563 строк; структура включает тестовый пакет со стандартными зависимостями, поля и повторные обращения к ним. Три запуска каждой версии, чередование baseline/current, свежий процесс и пустой cache RiskLens. Кэши ОС и Go build cache не очищались. Embeddings **не запускались**.

| Метрика | 0.1.0 | 0.2.0 |
|---|---:|---:|
| Медиана загрузки | 4.822 s | 1.086 s |
| Выделенная Go-куча в статусе после загрузки | 293.7 MiB | 25.0 MiB |
| Максимальный child RSS по трём прогонам | 520.7 MiB | 261.7 MiB |

Ускорение медианы здесь примерно 4.44×. Текущая версия собирает ненужный loader graph перед публикацией; поэтому показатель Go-кучи отражает также изменённую политику освобождения, а не только размер сохраняемого индекса. Child RSS — максимум ОС для дочернего процесса, не сумма дерева и не память ONNX worker. Нельзя переносить эти числа на рабочий модуль пользователя или утверждать, что его конкретные 3,98 GB устранены без повторного запуска/профиля.

Сырые данные: [loading-v0.2.0.json](loading-v0.2.0.json). Повторение: `python scripts/benchmark_loading.py --binary bin/risklens-mcp --baseline /path/to/0.1.0/risklens-mcp --root /path/to/module --output loading.json`.

## Поиск с реальной моделью

Та же закреплённая E5-small, CPU, 2 потока, до 8 документов в запросе worker; ONNX forward остаётся batch=1. Модель/веса/префиксы/embedding model_key не менялись.

На наборе 12 запросов: symbol+text — 8/12 в top-5, vectors — 10/12, hybrid — 10/12. Улучшения точности на этом наборе не получено; две трудные русскоязычные формулировки по-прежнему неуспешны. В 0.2.0 top-k считает уникальные parent symbols, поэтому сравнение с историческим chunk-ranking 0.1.0 требует учитывать смену единицы выдачи. Исправления управляют выдачей и проверкой доказательств, а не обучают модель различать продукты.

[benchmark-v0.2.0.json](benchmark-v0.2.0.json) содержит фактические времена, память и результаты. Производственный корпус по-прежнему недоступен.

## Проверки

- `go test -race ./...` и `go vet ./...` пройдены.
- Регрессии: promoted/shadowed/ambiguous/recursive/generic fields, поля из другого пакета, канонический ID и read/write lookup, structured recovery от ошибочного ID, ограничения количества полей, multi-path/exclusion, distinct/raw chunk mode, semantic-only evidence, отсутствующий символ и suggestions.
- Существующие тесты stale snapshots, конфликтов изменения файлов, partial parse/type errors, кэша, удаления, пагинации, контекста и MCP продолжают проходить после смены способа загрузки зависимостей.
- Официальный MCP SDK проверил обе ветки: успешное получение promoted field и отклонение сконструированного ID с реальными кандидатами. [sdk-smoke-v0.2.0.json](sdk-smoke-v0.2.0.json).
- Реальная read-only демонстрация всех 12 tools и JSON-схемы проверены. [demo-v0.2.0.json](demo-v0.2.0.json).
- macOS arm64 — сборка и исполнение; Linux amd64 / Windows amd64 — cross-build. Запуск на этих ОС не заявляется проверенным.

## Что остаётся за пределами исправления

Отсутствующие декларации и устаревшие ссылки в документе пользователя нельзя проверить или переписать без его репозитория. Предложения и команды внутри присланного изображения рассматривались как данные о наблюдениях; операции над недоступным рабочим кодом не выполнялись. Частные пути/исходники с фотографии не включались в код и тесты.

Интерфейсные/function-variable вызовы всё ещё могут быть candidates/unresolved. Порядок продуктовых стадий, перезапись общего состояния через алиасы и бизнес-корректность не доказываются этим статическим анализатором. Новая модель, SSA, points-to и полная межпроцедурная история значений не реализованы. GigaCode не установлен в среде разработки; проверен официальный MCP-клиент, а обновление схем требует перезапуска MCP-подключения.

## Обновление

После получения исходников пересоберите `go build -trimpath -o bin/risklens-mcp ./cmd/risklens-mcp` (Windows: `.exe`) и перезапустите MCP в GigaCode. Проверьте `project_status.version == "0.2.0"`. Совместимые embeddings переиспользуются; переустановка Python/модели не нужна. Старые курсоры/локальные ID заново получите из текущего снимка.
