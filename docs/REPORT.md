# RiskLens 0.1.0 — отчёт о поставке

Дата: 5 ноября 2026 года. Реализован работающий локальный прототип всех слоёв MVP: технический анализ, текстовый индекс, локальный inference и сохраняемый векторный индекс, гибридный поиск, сборка контекста, актуализация, MCP, skill, установка, тесты и демонстрация. Рабочая кредитная стратегия пользователя недоступна и не использовалась.

## Фактически проверенное окружение

- Apple M1, 16 GiB RAM; macOS-14.1.1-arm64-i386-64bit.
- Go 1.26.6; x/tools v0.52.0; Python 3.11.2; ONNX Runtime 1.23.2 CPU, tokenizers 0.22.1, NumPy 2.2.6.
- intfloat/multilingual-e5-small, ревизия 614241f622f53c4eeff9890bdc4f31cfecc418b3, FP32, 384 измерения, 512 токенов; 2 потока CPU, до 8 документов в запросе worker (ONNX forward batch=1), chunk_bytes 1200.
- Демонстрация: 9 Go-файлов, 488 строк, 8700 байт; 70 символов с локальными/файловыми контейнерами, 43 фрагмента; индекс загружен полностью без ошибок.

## Качество поиска с реальной моделью

Один закреплённый набор из 12 запросов: русскоязычные бизнес-формулировки, точные имена, код правила и похожие продуктовые реализации. Hit@k означает наличие хотя бы одного ожидаемого symbol_id среди первых k фрагментов; несколько фрагментов одного символа занимают несколько мест. Это не precision/recall на реальном репозитории.

| Режим | Hit@5 | Hit@10 | Первый запрос, медиана ms | Прогретый поиск, медиана ms |
|---|---:|---:|---:|---:|
| Символы + текст | 8/12 | 8/12 | 0.993 | 0.907 |
| Только векторы | 10/12 | 10/12 | 10.023 | 9.729 |
| Гибридный RRF | 10/12 | 10/12 | 9.884 | 9.851 |

Гибридный поиск улучшил результат относительно symbol+text на 2 запроса, но не превзошёл чистый векторный поиск ни по Hit@5, ни по Hit@10. Более высокая полнота гибрида на этом корпусе не доказана. Векторы помогают русским перефразировкам, не содержащим точных лексических совпадений.

Неуспешные запросы гибрида в top-5:

- «общая последовательность расчёта и заключительное уменьшение суммы».
- «изменения поля через указатель и увеличение счётчика».

Разбор причин: лексический канал не имеет русского стемминга и удаления стоп-слов, поэтому общие слова дают слабые совпадения. Длинный LongPipeline создаёт несколько близких фрагментов, занимающих места top-k. E5-small — общий multilingual encoder; он не обучался специально восстанавливать порядок стадий и семантику указателей в Go. Равновесное RRF не добавляет знаний, которых нет в каналах. Предметные комментарии демонстрации двуязычные и помогают retrieval; на коде без них качество может быть хуже.

Возможные расширения после проверки рабочей стратегии: обработка русских стоп-слов/морфологии, разнообразие результатов по parent symbol, настройка весов на отдельном validation-наборе, сравнение с Qwen3-Embedding или reranker. Эти расширения не объявляются реализованными и не подменяют проверку найденных определений и связей.

## Время, память и размер

- Первая индексация с пустым vector cache, включая запуск модели: **8.496 s**.
- Запуск с готовым vector cache и повторной загрузкой Go: **0.502 s**.
- Первый vector-запрос после этого запуска, включая холодный worker: **1435.626 ms**.
- Обновление одной функции (полный Go reload + пересчёт изменённого содержимого): **0.786 s**; hits 42/43.
- Cache directory: **209292 bytes** (204.4 KiB), включая небольшой служебный lock. Технический/текстовый индексы в памяти, их отдельных дисковых файлов нет.
- Пиковый sampled RSS дерева процессов сервера/worker/инструментов загрузки: **1107.875 MiB**. Опрос ps каждые 100 ms; это измерение с дискретизацией, не точный максимум allocator.
- Go heap в initial_status: **142.211 MiB**. Включает объекты загрузки до последующего GC; это не изолированный размер технического индекса.
- Файлы модели: примерно 470 MB ONNX + 17 MB tokenizer; Python-зависимости устанавливаются отдельно.

Cold здесь означает новый процесс и пустой векторный индекс. Кэши ОС и Go build cache не сбрасывались. Для каждого поискового случая выполнены 3 повтора; warm — медиана двух последних, общая таблица — медиана по 12 запросам. Фоновая нагрузка ОС полностью не контролировалась. Это один прогон на небольшой синтетике, не SLA и не оценка десятков тысяч строк. Сырой отчёт содержит каждую длительность и top-10: [benchmark.json](benchmark.json).

- `go test -race ./...` — пройдено; дополнительно пройден targeted race-тест embedding-процесса после фиксации локального reader.
- `go vet ./...` — пройдено.
- `go test ./...` в examples/strategy — пройдено.
- Проверены symbol identity, generic origins, shadowing, test variants, pointer/promoted-field accesses, interface candidates, unresolved function variables, callers замыканий, точное покрытие chunks без пересечений, filters/limits/context, пустые массивы JSON, cache reuse, удаление, line shifts, частичные parse/type failures, конфликт во время загрузки, stale cursors, failed refresh, exclusive cache, несовместимость модели и отмена зависшего worker.
- Детерминированный fake embedding provider используется только в unit tests. Результаты качества, demo и smoke получены с реальной ONNX-моделью.
- Официальный MCP SDK `mcp==1.26.0`: initialize, tools/list (12), tools/call, протокол 2025-11-25 — пройдено. [sdk-smoke.json](sdk-smoke.json).
- Реальный tokenizer/inference, L2-нормализация, длинный вход 2760 токенов / 6 окон — пройдено. [runtime-smoke.json](runtime-smoke.json).
- Read-only демонстрация всех 12 tools; хэши Go-исходников и go.mod/go.sum до/после совпадают. [demo-session.json](demo-session.json). Обычная демонстрация/smoke выполнялись в среде с ограниченным сетевым доступом; код worker не содержит сетевых запросов. Только setup-модель/зависимости и проверка публичных источников использовали сеть.

## Оставшиеся ограничения

Нет SSA/межпроцедурной истории значений, alias/points-to анализа, доказательства порядка исполнения или бизнес-корректности. Внешние зависимости типизируются, но не индексируются полностью; внешние local replace требуют явного refresh. Build-конфигурация одна. Технический индекс перестраивается полностью, векторный scan линейный. Во время векторизации нового снимка действует lexical-only режим. Прерванная новая векторизация не сохраняет частичный новый cache. После hard kill может остаться lock/дочерний процесс. Статические интерфейсные кандидаты не доказывают фактическую цель вызова. Переносимость inference зависит от CPU wheels и системных библиотек, реальный запуск на других ОС ещё нужен.
