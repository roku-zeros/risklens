# Архитектурное исследование с RiskLens

Исследуй затронутую часть монолита. Если задача отсутствует, составь общую карту и выбери один репрезентативный сценарий, явно указав охват. Представь результат в чате или по указанному пользователем пути. Исходники и конфигурация проекта доступны для чтения.

1. Вызови `index_status` и зафиксируй `index_snapshot` и ограничения анализа. Начни с `project_map`. Используй карту пакетов как ориентир. Границы бизнес-модулей устанавливай по точкам входа, сборке зависимостей, публичным контрактам и владению данными. Отделяй наблюдаемые зависимости от правил, которые реально проверяются кодом или тестами.
2. Проследи основной сценарий от точки входа до результата, записи данных и других побочных эффектов. Если задачу может изменить ошибка, исключение или повторная попытка, проследи и этот путь. Найди границу транзакции, если она видна в коде. Для пересечений модулей укажи направление вызова, контракт, владельца данных и исходную позицию.
3. Используй `search_symbols` для имён, `search_code` для поиска по смыслу и `get_callers` / `get_callees` для навигации по вызовам. Проверяй конкретные места через `get_source`. Группируй независимые чтения через `batch_tools` и проверяй ошибки отдельных элементов. Продолжай страницы, если обрезка может скрыть существенную зависимость.
4. Для функций сборки правил используй `rule_membership` с найденным ID функции. Учитывай явные элементы, guards и `unknown`. Раздельно описывай состав возвращаемого выражения, достижимость ветки и выполнение правила в конкретном сценарии. Кандидатная связь или частичное покрытие оставляют вывод открытым.
5. Проверь критичные ссылки строго через `get_source` или `verify_evidence` с ID снимка. Используй `freshness="snapshot"` только для исследования, где допустимы данные последнего снимка. При смене снимка перепроверь затронутые выводы. Если MCP недоступен, проверь доступный исходник напрямую и обозначь происхождение наблюдений.

Передай краткий отчёт, пригодный для следующего шага SDD:

- Снимок и охват. Укажи затронутые модули и известные ограничения.
- Карта модулей. Для каждого укажи ответственность, публичный вход, исходящие связи, владельца данных и позицию источника.
- Сценарии. Перечисли шаги, переходы, эффекты и релевантные тесты с исходными позициями.
- Ограничения и пробелы. Для каждого существенного вывода дай ID доказательства, ссылку `файл:строка` и статус «подтверждено исходником», «предположение» или «неизвестно». Укажи отдельно, если поведение подтверждено выполненным тестом. Для пробелов запиши, какое решение от них зависит.
